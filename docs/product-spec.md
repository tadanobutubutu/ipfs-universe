# Peerstellation Web版 再構築仕様

## 1. 目的

訪問直後から操作可能な3D宇宙を表示し、ブラウザ内のHelia/libp2pノードが実際に観測したピアをリアルタイムで反映する。表示する値は実測値または明示された「不明」のみとし、疑似ピア、乱数レイテンシ、架空の所在地、架空のプロトコルは使わない。

## 2. 正確性の境界

- 可視化対象は「このブラウザノードから観測できた範囲」であり、IPFS全体の完全なトポロジーではない。
- `peer:discovery` は発見、`peer:connect` は接続成立、`peer:disconnect` は切断として別状態で扱う。
- 線はローカルHeliaノードと接続済みピアの間だけに描く。遠隔ピア同士の線は、実データがないため描かない。
- レイテンシはping成功時だけミリ秒表示し、失敗または未対応なら「未測定」とする。
- プロトコルはidentify後のpeer storeに存在する値だけを表示する。
- IPアドレスからの地理推定、ウォレット接続、Notion/ncli連携は製品目的に不要なため実装しない。

## 3. 初回体験

1. HTML解析時点でCSS製の深宇宙背景と中心光を表示する。
2. 小さい起動モジュールがThree.jsシーンを作り、ネットワーク初期化より先に最初のフレームを描く。
3. Heliaは最初の描画後に遅延ロードする。
4. 初期化中も3D空間は操作でき、状態ラベルは「観測装置を起動中」と表示する。
5. Heliaが失敗しても3D表示、説明、再試行ボタン、静的なアクセシブル代替表示は残す。

### 性能予算

- デスクトップのLCP: 1.8秒以下を目標、2.5秒を失敗閾値とする。
- モバイルのLCP: 2.5秒以下を目標、4.0秒を失敗閾値とする。
- 初期JavaScript: 350 KiB gzip以下。Heliaは初期チャンクへ含めない。
- 3D描画: 通常12 draw call以下、DPR上限1.5、ノード上限512。
- 60 Hz端末: デスクトップp75で55 FPS以上。省電力または小画面では30 FPS以上。
- 長いタスク: 起動後5秒間に50 ms超を3件以下。
- メモリ: 接続・切断を30分繰り返して、切断済みノードのThree.jsリソースが増え続けない。

## 4. ビジュアル設計

### コンセプト

名称は「Peerstellation」。一般的な青い管理画面、過剰なガラスカード、意味のない16進数、常時表示ログを避ける。3D宇宙そのものを主役にし、UIは観測機器の薄いレイヤーとして扱う。

### 画面構成

- 左上: 独自の軌道ロゴと製品名。右上は接続状態・実接続数・モーション・一覧入口だけ。
- 初期画面: 凡例、p50/p95、scope、説明文を描画しない。情報はピア選択または一覧ダイアログへ退避する。
- 中央: ローカルHeliaノードを恒星として表示。発見ピアは淡い塵、接続済みピアは発光する天体、切断は残光を残して消える。
- ノード詳細: カーソルを重ねた時、キーボードで選択した時、またはタップした時だけ、対象ノードの画面座標へアンカーする。
- モバイル: 上部を1行に圧縮し、タップしたノードの横へカードを配置する。下部固定シートは使わない。

### 色と文字

- 背景: `#03050a`、深部: `#080b18`。
- 本文: `#f4f7ff`、補助文: `#bac5da`。
- 実接続: `#68f0d0`、発見: `#84a7ff`、警告: `#ffd089`、失敗: `#ff7f92`。
- 通常本文のコントラスト比は7:1以上、操作境界は3:1以上。
- 外部フォントを読込まず、`ui-sans-serif` と `ui-monospace` を使う。

### 動き

- ノード出現は600 ms以内、接続パルスは900 ms以内。
- 常時点滅、スキャンライン、グリッチ、パネル傾斜は使わない。
- `prefers-reduced-motion: reduce` では自動回転、カメラ慣性、パルス、残光を停止する。
- UIの「動きを止める」はOS設定に関係なく全アニメーションを停止できる。

## 5. アクセシビリティ

- WCAG 2.2 AAを必須、色コントラストと本文可読性はAAAを目標とする。
- `<main>`、見出し順、skip link、`<section>`、`<button>`、`<dialog>`相当の意味構造を持つ。
- canvasには短い代替名と詳細説明への参照を付ける。
- ピア一覧をDOMで提供し、各ピアをキーボードで選択できる。
- 接続数の変化は集約して通知し、ピアごとの高頻度イベントをlive regionへ連投しない。
- 200%文字拡大で情報を失わず、320 CSS px幅で横スクロールを発生させない。
- 44×44 CSS px以上の操作領域、見えるフォーカス、Escで閉じる操作を保証する。
- WebGL/WebGPUが使えない場合も、ノード状態とピア一覧を利用できる。
- axeの重大・深刻違反を0件、キーボードのみの主要導線完走を必須とする。

## 6. ネットワーク構成

- ブラウザ用の軽量libp2p構成を使い、WebRTC/WebRTC Direct/WebSocket/リレー、Noise、Yamux/Mplex、identify、ping、bootstrapだけを有効にする。
- bootstrapリストは依存する`@helia/libp2p`の公開リストを同じバージョンで固定し、アプリの表示データや疑似ピアとは混ぜない。依存更新時にリストも再確認する。
- WebRTCを利用できるよう、Helia/libp2pはWindow側で遅延初期化する。
- イベントを型付きの`PeerObservation`へ正規化し、描画へは最大10 Hzでバッチ反映する。
- `getConnections()`で初期スナップショットを取り、イベント登録前後の取りこぼしを補う。
- pingは接続済みピアに限定し、同時実行2件、5秒タイムアウト、各ピア30秒以上の間隔を設ける。
- Kuboの接続表はブラウザHeliaと別ソースである。Peer explorerの明示操作時だけ、CORSを許可した`127.0.0.1:5001`へ`/id`と`/swarm/peers?verbose=true`をPOSTし、`source: "kubo"`として表示する。自動アクセス、`*`許可、認証情報の転送はしない。
- ブラウザが観測できるのはローカルノードの直接接続だけであり、リモートピア同士の接続は共有された証拠がない限り線を引かない。
- IndexedDBには公開peer ID、状態、最終観測時刻、実測レイテンシだけを保存する。秘密鍵と完全なmultiaddrは保存しない。

## 7. WASMの責務

### Zig

- 512ノードまでの位置、速度、中心引力、反発、減衰を更新する。
- 固定メモリを使い、Three.jsのBufferAttributeはWASMメモリを直接参照する。
- TypeScriptへ毎フレーム配列コピーしない。
- `step(deltaSeconds, activeCount, motionScale)` を公開する。

### Rust

- ピアイベントのバッチから接続数、発見数、レイテンシp50/p95、ジッター、健全性スコアを算出する。
- 入力バッファと結果領域を生のWASM ABIで公開し、wasm-bindgenのJavaScript生成物を追跡しない。
- `analyze(count)` は境界値0、最大件数、未測定レイテンシを安全に処理する。

### TypeScript

- DOM、Heliaイベント正規化、状態管理、レンダラー連携、WASMロード、配信処理を担当する。
- リポジトリが所有する`.js`と`.jsx`は0件にする。依存物とビルド出力は追跡しない。

## 8. 安全性

- `innerHTML`へネットワーク由来文字列を渡さず、`textContent`を使う。
- CSPはインラインscript、`unsafe-eval`、外部フォントを許可しない。
- GitHub Actionsの権限はジョブ単位で最小化する。
- 第三者Actionは完全なコミットSHAへ固定するか、単純なコマンドへ置換する。
- PRコードをwrite tokenまたはOIDC付きAIエージェントへ渡さない。
- `npm audit --omit=dev` のhigh/criticalを0件、開発依存も例外理由なしのcriticalを0件とする。
- peer ID、エラー、URLをログへ出す際は長さを制限する。

## 9. Web専用化

- `local/`、Notion書き出し、ncli記述、`isLocal`による実装切替を削除する。
- 開発サーバーと本番は同じ実Heliaコードを使う。違いは診断ログとソースマップだけとする。
- IPFS Desktopは外部の開発・検証ノードであり、削除や同梱をしない。

## 10. 配信

- Cloudflare Workers Static Assetsを主配信にし、静的アセット要求を無料枠内で配る。
- Pinataは配信元ではなく、各リリース成果物のIPFSピンとDNSLink用CIDの生成に使う。
- HTMLを拒否するPinata public gatewayへ本番トラフィックを依存させない。
- デプロイ順は、検査、ビルド、Cloudflare静的配信、Pinataピン、DNSLink更新とする。
- 失敗時は直前のCloudflare版とIPFS CIDを保持する。

## 11. 品質評価

- LLMを実行しない製品のため、Instructor、Outlines、Guidance、Guardrails AI、NeMo Guardrails、Llama Guard、Prompt Guard、Ragas、Langfuse、Phoenixをランタイム依存へ追加しない。
- Promptfoo、DeepEvalも製品挙動を検査できないためCI依存へ追加しない。
- AI生成物の品質は、固定されたデザイン採点表、Claude Codeの独立査定、ブラウザ実測、axe、Lighthouse、Playwright、型検査、単体テストで評価する。
- 無関係なAI安全製品を大量導入して依存面と保守面を増やすことを、品質向上とは見なさない。

## 12. 合格条件

- 公開URLで1秒以内に宇宙背景、2.5秒以内に操作可能な3Dを確認できる。
- 公開環境で疑似ピア生成コードが実行されない。
- 実ピア接続を最低1件、peer IDと接続状態をDOM一覧と3Dの両方で確認できる。
- ZigとRustの両WASMが正しいWebAssembly moduleとしてビルドされ、ブラウザでロードされる。
- 手書き`.js/.jsx`、追跡`node_modules`、追跡`dist`が0件。
- 型検査、単体、WASM、E2E、axe、ビルド、依存監査の必須ゲートが成功する。
- Claude Codeの辛口再審査で、致命傷0件かつ80/100以上を得る。未達なら指摘を再実装する。
